          09 · Rules

          The logic behind every screen

          These rules keep the dashboard, the website, the planner and the reports in agreement.

          Daily limit follows WhatsApp

          waRegShare  = waQuota (200)
            − keptForInvitesAndOthers (20)
regCapacity = floor(waRegShare / messagesPerRegistration (2))
dailyLimit  = min(adminDailyLimit, regCapacity)     // 90

autoClosed =
     registrationsTodayIST ≥ dailyLimit
  || waSentLast24h         ≥ waQuota
          • Each registration can send two templates: registration_received (on submit) and registration_confirmed (on accept). So 200 messages cover about 100 registrations, and the daily limit can never be set above what WhatsApp can confirm.
          • Today the live WhatsApp limit counts a rolling 24 hours, while the intake limit resets at midnight IST. Either count both per IST day (simplest for "200 per day"), or keep the rolling window and reopen the form when WhatsApp frees a slot, showing that time.
          • "Reserved for other messages" keeps room for seva, team and card messages in later phases.

          Is the form open?

          open = websiteVisible && websiteRegSwitch
    && intakeSwitch && consentApproved
    && !autoClosedToday && !campaignFull
    && anyFestivalDayOpen

dayBookable(d) = dayOpen[d]
    && (dayCap[d] == null || registeredFor(d) < dayCap[d])
          • The first failing check becomes the reason shown on the dashboard and, in visitor‑friendly words, on the website.
          • A closed or full day stays visible on the form, greyed with a label, so visitors understand why they can't pick it.

          Registration status

          newaccept →acceptedplan →assigned (per day + slot)
          any time before the card is collected → cancel (reason) →cancelled
          • The WhatsApp confirmation is tracked separately: sent, failed, queued or no consent.
          • Only accepted registrations appear in the planner.

          Sevas, planner and teams

          seva       { name, description, active }
need       { seva, day, slot, count }
assignment { person, seva, day, slot }   // one per person per day‑slot
team       { seva, leader, viceLeader }  // members = people assigned to the seva
          • A person can be assigned only to a day and slot they marked as available on the form.
          • One team per seva. The leader and vice‑leader must be members, and must be two different people.
          • The ID card shows the person's seva, team, leader and days.

          Invitation quota and mode switch

          invitationsNow = max(0, min(200 − 50 − invSent24h,
                            200 − allSent24h))
daysNeeded     = ceil(remainingEligible / 150)
canSend        = mode == invitation && approved
              && templateOk && posterOk && senderReal
          • Switching to invitation mode pauses registration messages (they queue). If the form is still open, offer "close the form and switch".
          • The 24‑hour count never resets when the mode changes. "Uncertain" messages are never retried automatically.

          Security and privacy (keep the live behaviour)

          • Mobiles masked to the last 4 digits everywhere; full number or photo reveal is audited.
          • Refused numbers are never messaged; "a mobile number is not consent".
          • The uploaded file isn't stored, only the mapped columns; invitation lists get a delete‑after date.
          • Authenticator second step for admin roles, 8 one‑time recovery codes, sessions end after 30 min idle or 8 h, password resets only by super admin.
          • Campaigns need a second person's approval. Every admin action goes to the audit log in UTC, shown in IST.

          • One primary (solid maroon) button per screen or sheet: the next step.
          • Destructive actions are outlined red and always confirm with a reason.

          • Every count shows its limit: "૩ / ૧૮૦".
          • Tap targets 44px. Phone: bottom tabs. Phone landscape: two panes. Tablet landscape: sidebar.
